# IntuneGet v0.8.0-rc.1

This release candidate prepares the first product Docker release since v0.7.1. It is a preview for evaluating the current self-hosted application. It does not replace the stable `latest`, `0.7`, or major version image aliases. Shared packager npm releases and QA packager pins are separate and unchanged by this release.

## Self-hosting changes

The Docker image prepares `/data` for the nonroot application user, UID and GID 1001. A fresh named volume mounted there can initialize SQLite and retain the database across container recreation. Existing nonempty volume ownership is preserved. Bind mounts, custom container users and `volume-nocopy` still require compatible permissions. An empty volume left by a failed first start receives Docker's normal image directory initialization when mounted into a new container.

SQLite now uses versioned, transactional migrations and includes the local jobs and application update policy adapters. Catalog and QA information can come from the published catalog snapshot. Features that use live QA coordination or hosted service state still require Supabase; this release does not establish a completely Supabase-free packaging and upload workflow.

The product also includes the navigation updates bell and clearer deployment setup messages. Hosted catalog qualification, shared packaging changes and a successful website deployment do not establish successful customer upload or installation.

## Runtime and upgrade impact

The image moves from Node.js 20 to Node.js 26.5 and Next.js 16. This is a minor product release candidate rather than a patch on the older `0.7` image channel.

Back up the SQLite volume before upgrading. The application applies forward migrations on startup. Downgrading an upgraded database to v0.7.1 is not qualified; restore the backup to return to the old release. Preserve your existing authentication configuration and review the maintained `.env.example` for optional settings.

To evaluate the candidate image, use `ghcr.io/ugurkocde/intuneget:0.8.0-rc.1` with `DATABASE_MODE=sqlite`, `DATABASE_PATH=/data/intuneget.db`, and a named volume mounted at `/data`. The documented Compose configuration builds from source and is a separate distribution path.

## Verification and limitations

The release pipeline requires native Linux amd64 and arm64 checks of the exact published digest. Each architecture must pass fresh volume initialization, recreation persistence and migration of a disposable v0.7.1 database containing a completed fixture job. Critical vulnerability scanning and digest signing must pass before the draft release is published. These checks run during release; this note does not claim they have already completed.

Windows Docker Desktop confirmation for the reported case in issue1272 remains pending. Image and database checks do not test Graph permissions, tenant upload, device installation or every feature added since v0.7.1. Health can report `degraded` when optional services are absent; `services.database` identifies SQLite availability.

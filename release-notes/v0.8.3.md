# IntuneGet v0.8.3

This Docker image update brings the Next.js security fix from [#1650](https://github.com/ugurkocde/IntuneGet/pull/1650) to installations you host. The local Windows packager has its own version and release process.

## Framework security update

Next.js and its matching lint configuration are pinned to 16.4.1. This fixes GHSA-2464-fhr4-w9xw, GHSA-673q-mjm6-r5xr and GHSA-p3m5-59mp-jv5r. Vulnerability scanning remains enforced.

The image also contains all other changes merged since v0.8.2, including deployment validation and resume fixes, Reader installer metadata, catalog sync efficiency, catalog releases and icons, and QA security evidence handling. See the full changelog below for the complete range.

## Upgrade notes

After publication, use `ghcr.io/ugurkocde/intuneget:0.8.3` for the patched version. Back up the database and retain the existing data volume and server configuration when recreating the container. See the [deployment guide](https://github.com/ugurkocde/IntuneGet/blob/v0.8.3/docs/SELF_HOSTING.md) for deployment configuration.

## Verification and known limitations

The existing release pipeline requires native Linux amd64 and arm64 checks of the exact image digest, including fresh SQLite initialization, persistence after container recreation, and an upgrade from a disposable v0.7.1 database. Critical vulnerability scanning and digest signing must pass before stable aliases are promoted.

Windows Docker Desktop confirmation is not supplied by those Linux image checks. Image verification does not establish Microsoft Graph permissions, customer upload completion or device installation success. Existing application security holds remain in force.

# IntuneGet v0.8.6

This server and Docker image release includes the SQLite automatic update detection fix from [#1758](https://github.com/ugurkocde/IntuneGet/pull/1758) and assignment migration fix from [#1820](https://github.com/ugurkocde/IntuneGet/pull/1820), addressing the automatic update problems in [#1757](https://github.com/ugurkocde/IntuneGet/issues/1757).

## SQLite automatic update detection

Each queued automatic update now carries the current resolver detection rules. Policies with saved PSADT settings refresh their managed marker rules and use the same normalized scope for the rules and queued job. Legacy policies without those settings or current rules retain their prior rules and scope. Saved policies are unchanged, custom detection remains held, and curated cart data remains authoritative.

## SQLite assignment migration

Automatic updates now carry the saved assignment migration choice to the existing uploader. An explicit disabled choice and an absent choice remain false. Supersedence behavior is unchanged.

## Runtime security update

Both Docker stages use the digest pinned Node.js 26.13.1 Alpine image, including the November 11 security fixes. The runtime stays on Node.js 26 and retains the existing non-root user and image security checks.

## Upgrade

After publication, use `ghcr.io/ugurkocde/intuneget:0.8.6`. Back up the database and retain the existing data volume and configuration when recreating the container. The local packager has its own release process and needs no version change for this server fix.

The release keeps native amd64 and arm64 SQLite initialization, persistence and upgrade checks, vulnerability scanning, exact digest signing and verified stable tag promotion.

## Known limitations

This fix does not remove older Intune apps, change assignments or add team sharing. Those parts of #1757 remain separate. No customer deployment, device installation or Windows Docker Desktop confirmation is claimed by the source tests or native Linux image checks.

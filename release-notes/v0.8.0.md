# IntuneGet v0.8.0

This is the first stable product release since v0.7.1. It focuses on self-hosted Docker installations that run with SQLite and without Supabase, and it adds several deployment and assignment improvements for every installation. After the release pipeline passes, the image becomes the new `latest`, `0.8` and `0` channel.

The local Windows packager is released separately on npm as `@ugurkocde/intuneget-packager` 1.4.1. If you package locally, update it as well with `npm install -g @ugurkocde/intuneget-packager@1.4.1`, because several packaging fixes listed below live in the packager rather than in this image.

## Self-hosting with SQLite

The Docker image prepares `/data` for the nonroot application user, UID and GID 1001. A fresh named volume mounted there can initialize SQLite and keeps the database across container recreation. Existing nonempty volume ownership is preserved. Bind mounts, custom container users and `volume-nocopy` still require compatible permissions. Related to #1272.

SQLite now uses versioned, transactional migrations. App update policies, auto update history, update check results and curated licence attestations are stored in the local database.

Deployment jobs are created in SQLite and start queued for the local packager. Recent source builds could fail this insert because of a parameter count mismatch; this release contains the fix and regression coverage against a real SQLite database. Related to #1107 and #458.

Discovered app claims are stored in a new local table. Previously a claim returned a server error without Supabase, and Claim All marked every app as failed. Related to #1107.

Inventory, reports, analytics and the other dashboard pages no longer fail when Supabase is not configured. Pages backed by Microsoft Graph read Graph directly, analytics come from the local database, and hosted only areas return an empty result or a clear message. Related to #1434.

Queued, packaging, uploading and QA waiting deployments can be cancelled, and finished deployments can be dismissed, without Supabase. Both actions previously returned HTTP 500 in SQLite mode. Related to #451.

The notification settings explain what is missing instead of returning HTTP 500. Email and webhook notifications need Supabase, and email also needs Resend. The settings cards name the missing requirement and link to the setup guide. Related to #453.

## Features and improvements

- Deployment starts and failures, and local packager job results, are written to the server log, so self-hosted operators can follow them in the container log. Logged values are redacted for URLs, tokens, credential parameters, Basic and Bearer authorization and connection string passwords, and control characters are replaced so a value cannot forge extra log lines. Related to #483.
- When a deployment cannot start, the cart shows a known, app specific reason where one exists instead of a generic error.
- Editing a cart item now offers every advanced option, including the description override and the post install and post uninstall commands, not only the install and uninstall command overrides. Related to #162.
- When adding assignment groups you can choose the intent first: Required, Available, Uninstall or Update Only. Exclusions keep their existing behavior. Related to #1203.
- Application details show assignment group names. When a name cannot be read, the label says whether the group was deleted or the app lacks permission to read it, and the full group ID is shown on hover. Related to #164.
- Existing tenant deployments are shown before you choose apps from the catalog.

## Fixes

- A QA gate block at packaging dispatch, such as a VirusTotal verdict, a reviewed compatibility block or a missing QA pass, is now reported as a failed validation with its real message instead of a generic workflow start failure at the authentication step. Related to #642.

## Security

- Every value that IntuneGet embeds in generated PowerShell is now encoded for its exact context. This includes typographic quote characters that PowerShell also treats as string delimiters, and `$` and backtick expansion in double quoted strings. In this image the change covers the requirement and MSIX detection scripts the app generates. The experimental Azure DevOps pipeline template in the repository is hardened the same way.
- Display names used in registry uninstall markers have control characters and Unicode line terminators removed, so an unusual app name cannot change the generated uninstall command.
- The matching packaging script changes, including refusing malformed or hidden uninstall markers and writing generated scripts with a UTF-8 byte order mark for Windows PowerShell 5.1, ship in packager 1.4.1 for local packaging and through the hosted packaging pipeline separately from this image.

## Runtime and compatibility

The image moves from Node.js 20 to Node.js 26.5 and Next.js 16. Source installations need Node.js 22 or later.

## Upgrade notes and migrations

Back up the SQLite volume before upgrading. The application applies forward migrations on startup and moves the SQLite schema to version 5. Downgrading an upgraded database to v0.7.1 is not qualified; restore your backup to return to v0.7.1. An older build that already uses the migration runner but predates schema version 5 leaves the new `claimed_apps` table untouched and keeps working; claims recorded by v0.8.0 are simply not shown there.

Preserve your existing authentication configuration and review the maintained `.env.example` for optional settings. Use `ghcr.io/ugurkocde/intuneget:0.8.0` with `DATABASE_MODE=sqlite`, `DATABASE_PATH=/data/intuneget.db`, and a named volume mounted at `/data`. The documented Compose configuration builds from source and is a separate distribution path.

## Verification and known limitations

The release pipeline requires native Linux amd64 and arm64 checks of the exact published digest. Each architecture must pass fresh volume initialization, recreation persistence and migration of a disposable v0.7.1 database containing a completed fixture job. Critical vulnerability scanning and digest signing must pass before the stable aliases move and the release is published.

Windows Docker Desktop confirmation for the reported case in issue #1272 remains pending. Image and database checks do not test Graph permissions, tenant upload, device installation or every feature added since v0.7.1. Health can report `degraded` when an optional service such as the packaging pipeline is not configured; `services.database` shows SQLite availability.

Features that use live QA coordination, notifications, MSP organizations or other hosted service state still require Supabase. This release does not establish a completely Supabase-free workflow.

# IntuneGet v0.8.2

This Docker image update brings the deployed app settings fix from [#1568](https://github.com/ugurkocde/IntuneGet/pull/1568) to self hosted installations. The local Windows packager has its own version and release process.

## Deployed app settings

Changes made in the deployed app settings dialog are now saved to the matching SQLite deployment record. The lookup and save are scoped to the user, tenant and Intune app, so another deployment's settings are not selected or overwritten.

If a matching saved deployment configuration is missing, the request stops before changing Intune. If Intune accepts an update but saving the configuration fails, the response reports that distinction instead of claiming that both operations succeeded.

The image also contains the other changes already merged since v0.8.1. See the full changelog below for those changes.

## Upgrade notes

After publication, use `ghcr.io/ugurkocde/intuneget:0.8.2` for the fixed version. Back up the database and retain the existing data volume and server configuration when recreating the container. See the [self hosting guide](https://github.com/ugurkocde/IntuneGet/blob/v0.8.2/docs/SELF_HOSTING.md) for deployment configuration.

## Verification and known limitations

The existing release pipeline requires native Linux amd64 and arm64 checks of the exact image digest, including fresh SQLite initialization, persistence after container recreation, and an upgrade from a disposable v0.7.1 database. Critical vulnerability scanning and digest signing must pass before stable aliases are promoted.

Windows Docker Desktop confirmation is not supplied by those Linux image checks. Image verification does not establish Microsoft Graph permissions, customer upload completion or device installation success.

# IntuneGet v0.8.4

This app and Docker image update brings installer command parsing, version resolution, and clearer validation messages to installations you host. It also includes improvements to Supabase backed packaging and the hosted QA service. The local Windows packager has its own version and release process.

## Installer and deployment fixes

Plain EXE command overrides now preserve one bounded action verb followed by literal switches. Extra operands, paths, URLs, shell syntax, and wrapper arguments remain refused. Deployment errors also explain when a plain EXE requires explicit silent switches or a reviewed adapter, while appended diagnostic text stays private. See [#1698](https://github.com/ugurkocde/IntuneGet/pull/1698) and [#1697](https://github.com/ugurkocde/IntuneGet/pull/1697).

WinGet manifest versions with a `v` prefix now resolve and sort correctly. Supported installation scopes and exact uninstall identities were corrected for several catalog applications. These changes do not establish a successful installation in a customer tenant. See [#1672](https://github.com/ugurkocde/IntuneGet/pull/1672) and the full changelog.

## Supabase backed packaging and hosted QA

Packaging now also waits when a required WinGet prerequisite has missing, stale, held, or adverse reputation evidence, including when installation validation is overridden. This read only check does not start a scan or release a security hold. It applies when Supabase server credentials are configured. Standalone SQLite mode without a Supabase server configuration keeps its existing local packaging path. See [#1689](https://github.com/ugurkocde/IntuneGet/pull/1689).

The hosted QA view shows more accurate security hold reasons and recheck dates. Retryable preflight failures explain that verification was blocked and the application was not tested. Hosted evidence handling and background intake also received fixes. These notes do not assert that a database migration has been applied to any particular installation. See [#1667](https://github.com/ugurkocde/IntuneGet/pull/1667) and [#1666](https://github.com/ugurkocde/IntuneGet/pull/1666).

Verified curated catalog releases and application icons are included in the full changelog.

## Upgrade notes

After publication, use `ghcr.io/ugurkocde/intuneget:0.8.4`. Back up the database and retain the existing data volume and server configuration when recreating the container. See the [deployment guide](https://github.com/ugurkocde/IntuneGet/blob/v0.8.4/docs/SELF_HOSTING.md) for configuration.

## Verification and known limitations

The existing release pipeline requires native Linux amd64 and arm64 checks of the exact image digest, including fresh SQLite initialization, persistence after container recreation, and an upgrade from a disposable v0.7.1 database. Critical vulnerability scanning and digest signing must pass before stable aliases are promoted.

Windows Docker Desktop confirmation is not supplied by those Linux image checks. Image verification does not establish Microsoft Graph permissions, customer upload completion, or device installation success. Existing application security holds remain in force.
